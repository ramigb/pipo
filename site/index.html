01 / THE ARTIFACT

A pipeline is just a file.

YAML you can read, diff, review and version.
The builder edits the same artifact.

≡ heartbeat.pipoDownload ↓ 
pipo: 1
name: heartbeat
input:
  via: schedule
  with: {every: 5s, payload: {status: alive}}
nodes:
  stamp:
    from: input
    transform: map
    with:
      data: {status: "${data.status}", tick: "${meta.source}"}
output:
  from: stamp
  to: file
  with: {path: ./out/heartbeat.jsonl, format: jsonl}
delivered:
  check: line_contains
  with: {value: "${meta.packet_id}"}
  within: 5s

02 / THE CONTRACT

Execution is not delivery.

The code returned. Did the output get there?
Pipo tracks that boundary explicitly.

A STEP SUCCEEDINGtrigger → steps → execution succeededis part of the journey

The output connector reports a successful write and the configured delivery check passes. That packet is delivered.

↳ failure → configured retries → DLQ / inspect & replay

Verification is explicit. Default ack trusts the connector's success report. Configure checks such as record_exists, line_contains, follow_up or external when your destination needs more evidence. none skips verification.

At-least-once, with idempotency keys. Exactly-once delivery is not guaranteed. A repeated step can repeat a side effect. HTTP destinations must honour the key; Telegram sends can duplicate. Invalid input is rejected, filters can end packets as filtered, and error policies can pause, halt or escalate. Read the guarantees ↗

03 / THE JOURNAL

The process stops.
The trail stays.

Each pipeline has its own runner process and SQLite WAL journal. Packets are recorded before input acknowledgement. Every node result is committed before the next node runs.

After a crash, the runner resumes from the last committed node. Work beyond that boundary may run again. Packets keep the version that accepted them.

04 / THE OPERATING MODEL

Human-readable.
Agent-operable.

Author, operator, editor. Agency can move
back and forth; the pipeline remains.

Same pipeline. Same operating language.

Both can create and inspect the file, validate it, test it, operate pipelines, diagnose failures, replay dead-lettered packets and work with versions.

createinspecteditchecktestoperatediagnosereplayversionrollback

Explicit policy boundaries.

Agent access uses scoped tokens and pipeline policies. Permitted changes follow propose → validate → optional dry run → apply, creating a new version with an audit trail.

Output, delivery, secrets, agent policy and agent budgets stay human-controlled. A granted edit can apply automatically; a proposal can also be held. In-flight packets finish on their pinned version.

B / EXEC AS A STEP

Your machine.
Your programs.

Run ffmpeg, pandoc or your own scripts as a tap or transform. Arguments go directly to the program, with declared outputs and a timeout.

watch / *.mp3↓transform: exec / ffmpeg↓video file + JSONL record

Programs run as you, with no shell and no sandbox. A crash before the step commits can run the program again.

See audio → video ↗

An agent inside a pipeline is separate from an agent operating Pipo. You can use either, both, or neither.
