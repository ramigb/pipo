pipes + i/o / local / open source / early days

Small pipelines.
Big receipts.

Pipo runs the little glue jobs you keep rewriting: a webhook into SQLite, a folder into ffmpeg, a Telegram bot that answers back. Each one is a tiny YAML file on your machine. Write it yourself, or ask Claude to. Pipo journals every packet and shows you where it landed.

            Journaled before “ok”.
            A packet is written to the pipeline's SQLite journal before the sender is acknowledged.
          
        • 
          
      • 
            One commit per step.
            After a crash, a packet resumes from its last committed step. The step that was running runs again.
          
        • 
          
      • 
            Delivered means checked.
            The write succeeded, and if you ask, Pipo looks for the row, the line or the follow-up.
          
        • 
          
      • 
            At-least-once, said out loud.
            Not exactly-once. Writes are idempotent on a key; a side effect can still repeat.

        What Pipo is and isn't
        
          
        
            
        
              
        pipo is
        
              
          
                
        • one readable file per pipeline, in Git
          • 
                
        • for personal and small-team glue
          • 
                
        • running on your laptop or a box you own
          • 
                
        • happy to be written and run by an agent
          • 
              
        
            
        
            
        
              
        pipo isn't
        
              
          
                
        • a hosted service or a SaaS
          • 
                
        • a Kafka, Airflow or BPM replacement
          • 
                
        • exactly-once (it's at-least-once)
          • 
                
        • finished: no packaged release yet
          •
